# 학생 개인정보 취급 원칙 (교과 불변)

> 세 스킬 모두 이 문서를 따른다. 교과가 바뀌어도 달라지지 않는다.

---

## 1. 먼저 알아야 할 사실

**이 도구에 입력한 내용은 학교 밖으로 나갑니다.**

Claude Code는 대화 맥락을 Anthropic의 서버로 전송해 처리합니다. 붙여넣은 성적일람표, 학생 답안, 수행평가 산출물도 예외가 아닙니다. 로컬에서만 도는 프로그램이 아닙니다.

그래서 학생 개인정보를 다루는 일반 원칙이 그대로 적용됩니다.

- 교육부·교육청 공동 「수행평가 시 AI 활용 관리 방안」은 **이름·학번·생년월일·주소·연락처·가족관계·타인 사진** 등 개인식별 정보를 생성형 AI에 입력하지 않도록 지도할 것을 명시합니다.
- 경기도교육청 「교사용 가이드라인 — 생성형 인공지능 활용교육」은 **꼭 필요한 정보만 입력**하고 대화 저장 기능을 끌 것을 권합니다.
- 학교가 쓰는 소프트웨어는 개인정보 보호법상 **최소 수집·안전조치** 기준을 충족해야 합니다.

> 학생 지도에 적용하는 기준을 **교사 자신에게도 똑같이** 적용해야 합니다.
> 소속 학교와 시도교육청의 지침이 이 문서보다 우선합니다.

## 2. 입력해도 되는 것 / 안 되는 것

| | 예 |
|---|---|
| ✅ **된다** | 성취기준 코드와 진술문 · 문항·지문·선지 · 채점기준 · 평가계획 |
| ✅ **된다** | **문항 단위 집계** — "3번 정답률 45%, 답지반응 ① 81명 ② 1명 …" |
| ✅ **된다** | **익명 분포** — "A 27명, B 40명, C 45명, D 25명, E 28명, 미도달 15명" |
| ✅ **된다** | **익명 라벨** — "학생 A는 B수준, 3·7번 오답" |
| ❌ **안 된다** | 이름 · 학번 · 생년월일 · 주소 · 연락처 · 가족관계 · 사진 |
| ❌ **안 된다** | 성적일람표 원본 (이름 열이 붙어 있다) |
| ❌ **안 된다** | 학생 답안·수행 산출물 **원문** (이름이 적혀 있거나 내용으로 식별된다) |
| ❌ **안 된다** | 학교명 + 학년 + 반 + 번호 조합 (조합하면 특정된다) |
| ❌ **안 된다** | 세부능력 및 특기사항 초안 (학생별 관찰 기록이다) |

**간접 식별에 주의합니다.** 이름을 지워도 "3학년 2반 유일한 전학생", "○○대회 수상자"처럼 **조합하면 누구인지 알 수 있는 서술**은 개인정보입니다. 학생 글에 담긴 가족사·건강·진로 같은 내용도 마찬가지입니다.

## 3. 익명화하는 법

### 성적 자료

```
[원본]  1/1 김○○  28.41  29.16  …  93  A  1
        ↓ 이름·반·번호 열 삭제, 필요하면 순번만
[익명]  1        28.41  29.16  …  93  A  1
```

문항 분석만 할 거라면 **학생 행 자체가 필요 없습니다.** 문항별 집계만 넘기면 됩니다.

```
문항,성취기준,점검성취수준,예상난이도,배점,정답,응답1,응답2,응답3,응답4,응답5
3,[…],C,보통,4,4,9,14,25,120,12
```

### 학생 답안·산출물

원문을 그대로 넣지 말고 **무엇이 어느 수준인지의 특징**으로 바꿔 씁니다.

```
[원본] "저는 초등학교 5학년 때 할머니가 ○○병원에 입원하셨을 때…"
   ↓
[대체] "개인적 경험을 계기로 제시하고 자료 3종을 통합했으나
        자료 간 연결이 일반적 서술에 그친 답안"
```

채점기준을 다듬으려고 실제 답안이 꼭 필요하다면, **이름·학교·구체적 지명·병원명·가족 관계를 지우고** 넣습니다.

## 4. 입력 전 점검

```bash
python scripts/check_pii.py 성적자료.csv
```

이름·학번·생년월일·연락처 같은 열과 주민등록번호·전화번호·이메일 패턴을 찾아 **어느 줄에 무엇이 있는지** 알려 줍니다. 기계적 검사이므로 통과했다고 안전이 보장되지는 않습니다. **간접 식별은 사람이 판단해야 합니다.**

---

## 5. 스킬이 지켜야 할 것

- 사용자가 식별정보가 든 자료를 주면 **분석을 시작하지 말고 익명화를 먼저 요청한다.** 어느 열·어느 부분을 지워야 하는지 구체적으로 짚어 준다.
- 산출물에 학생 이름이나 식별 가능한 서술을 **재생산하지 않는다.**
- 개별 학생의 세부능력 및 특기사항을 **대신 쓰지 않는다.** 수준별 서술 틀까지만 만든다.
- 사용자가 사정을 알고도 진행을 요청하면, **한 번 더 사실을 알리고** 그래도 원하면 따른다. 다만 산출물에 식별정보를 남기지 않는다.

## 6. 이미 입력했다면

당황할 일은 아니지만 그냥 두지도 않습니다.

1. **대화를 종료**하고 새 세션에서 다시 시작합니다.
2. `.work/` 에 남은 중간 산출물을 확인해 지웁니다. 이 디렉터리는 저장소에 커밋되지 않지만 **로컬 디스크에는 남습니다.**
   ```bash
   grep -rl "지울 이름" .work/ 2>/dev/null   # 확인
   rm -rf .work/                              # 정리
   ```
3. 한글 문서로 이미 출력했다면 그 파일도 확인합니다.
4. 학교의 개인정보 처리 방침에 따라 보고가 필요한 사안인지 판단합니다. 판단이 서지 않으면 **학교 개인정보 보호 담당자에게 문의**합니다.
