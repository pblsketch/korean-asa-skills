# 성취평가 결과 분석

## 이 스킬의 전제

결과 분석의 목적은 **성적 확정이 아니다.** 셋이다.

| 목적 | 무엇을 보는가 |
|---|---|
| 학생의 성취도·발달 파악 | 성취기준별 도달 정도, 수준별 수행 특성의 차이 |
| **평가도구의 타당성 검토** | 오류·문제 소지 문항 → 향후 제작 개선 |
| 교수·학습 개선 피드백 | 강·약점 파악 → 후속 학습 지원 |

세 번째만 하고 두 번째를 건너뛰기 쉽다. **평가도구를 스스로 검증하는 것이 이 스킬의 절반이다.**

## ⚠ 학생 개인정보

**이 도구에 입력한 내용은 학교 밖으로 나갑니다.** Claude Code 는 대화 맥락을 외부 서버로 전송해 처리합니다. 성적일람표를 그대로 붙여넣으면 학생 개인정보가 그대로 전송됩니다.

교육부·교육청 공동 지침이 생성형 AI 입력을 금지한 개인식별 정보는 다음과 같다.

> **이름 · 학번 · 생년월일 · 주소 · 연락처 · 가족관계 · 타인 사진**

이 스킬은 **문항 단위 집계와 익명 분포만** 다룬다. 개인별 피드백이 필요하면 "학생 A는 B수준, 3·7번 오답" 같은 익명 라벨로 받는다.

사용자가 식별정보가 든 자료를 주면 **분석을 시작하지 말고, 어느 열을 지워야 하는지 짚어 익명화를 먼저 요청한다.**

```bash
python scripts/check_pii.py <파일>     # 입력 전 기계 점검
```

간접 식별("3학년 2반 유일한 전학생")은 기계가 잡지 못하므로 사람이 판단해야 한다.
자세한 원칙과 익명화 방법은 `core/privacy.md`.

## 절차

### 1단계 — 자료 확보

필요한 것과 나이스 경로는 `core/result-analysis.md` §7 에 있다. 최소한 이것이 필요하다.

- 문항정보표 (성취기준 · 점검 목표 성취수준 · **예상 난이도** · 배점 · 정답)
- 실제 정답률, 답지반응 분포
- 성취수준별 학생 분포
- 예상 평균(출제 계획표) vs 실제 평균

**예상 난이도가 없으면 분석의 절반이 불가능하다.** 그 경우 그렇다고 말하고, 다음 학기에는 문항정보표에 기록하도록 안내한다.

`asa-item` 이 만든 `.work/items/<코드>.json` 이 있으면 문항정보표로 바로 쓴다.

### 2단계 — 수치 계산

```bash
# asa-item 이 만든 문항 정보가 있으면 뼈대를 자동 생성한다 (응답 인원만 채우면 된다)
python scripts/analyze_results.py --from-items .work/items/<코드>.json > results.csv

# 없으면 빈 서식부터
python scripts/analyze_results.py --template > results.csv

python scripts/analyze_results.py results.csv       # 분석

# 성취수준별 분포가 있으면 함께 넣는다 (5단계에서 쓴다)
python scripts/analyze_results.py results.csv   --dist "A:27,B:40,C:45,D:25,E:28,미도달:15" --common
```

> `--dist` 는 **집계값만** 받는다. 학생별 점수나 명단은 넣지 않는다.
> 미도달 인원 파악에는 집계로 충분하고, 명단은 교사가 나이스에서 본다.
> `--common` 을 붙이면 공통과목(성취율 40% 이수 기준 적용)으로, 없으면 선택과목으로 해석한다.

직접 계산하지 말고 스크립트를 쓴다. 정답률·난이도 구간·갭·사문항 선지·수준 역전·66% 대비를 결정적으로 뽑아 준다.

### 3단계 — 3-Focus 분석

`core/result-analysis.md` §2 의 틀을 따른다.

| 초점 | 질문 |
|---|---|
| 전반적 성취 | 기대한 수준에 도달했는가 · 특이하게 높거나 낮은 집단이 있는가 |
| 집단별·수준별 | 집단 간 차이가 있는가 · 수준별 이해도 차이는 어느 정도인가 |
| **예상과 실제의 차이** | 지나치게 쉽거나 어려웠던 문항은 · 의도하지 않은 답지반응이 있는가 |

### 4단계 — 오개념 추론 ★ 배제부터 한다

**정답률이 낮다고 모두 오개념이 아니다.** 다음 넷을 먼저 배제한다.

| # | 배제 대상 | 신호 |
|---|---|---|
| 1 | **문항 결함** | 복수정답·정답 없음·발문 모호. **상위권도 함께 틀림** |
| 2 | **변별도 저해 선지** | 응답률 5% 미만 선지 존재 → 실질 선택지 수가 줄었다 |
| 3 | **미학습** | 수업에서 다루지 않았거나 시간이 부족했던 내용 |
| 4 | **시험 운영** | 뒷번호 정답률 급락(시간 부족), 무응답률 상승, 지시 오류 |

> **사문항 선지 해석 주의** — 정답률이 높은 하위 수준(D·E) 문항에서 저응답 선지가 여러 개 나오는 것은 정상이다. **상위 수준(A·B) 문항에서 나오면** 변별해야 할 지점에서 실질 선택지가 줄어든 것이므로 교체를 검토한다.

넷을 배제한 뒤에야 `subject/misconceptions.md` 의 패턴 목록에서 가설을 세운다.

**가장 강한 오개념 신호**: 최다 응답이 오답이고 그 비율이 정답률보다 높을 때. 학생 다수가 같은 방향으로 틀렸다는 뜻이다. 해당 선지가 무엇을 유도했는지 지문·발문과 대조해 특정한다.

**단정하지 않는다.** 답지반응 분포는 가설을 좁힐 뿐이다. 결론은 항상 이렇게 낸다.

> "⑤번에 35%가 몰린 것은 K-01(지문 근거 미탐색) 또는 K-05(인접 개념 혼동)로 보인다. **학생 상담이나 후속 형성평가로 확인이 필요하다.**"

### 5단계 — 최소 성취수준 대상 식별

**과목 유형을 먼저 확인한다.** 2026학년도부터 학업 성취율 40% 이수 기준은 **공통과목에만** 적용된다.

| 과목 | 무엇을 뽑는가 |
|---|---|
| **공통과목** | **미도달(40% 미만) 인원**과 E 수준 인원 → 미도달은 **보장지도 대상** |
| **선택과목** | E 수준 인원(60% 미만). **미도달 구분이 없다.** 성취율로는 미이수가 되지 않는다 |

- E 비율이 지나치게 높거나 낮지 않은가
- 이전 평가 대비 변화는
- (공통과목) 미도달 → **최소 성취수준 보장지도 대상**으로 즉시 연결한다 (`asa-guide` 작업 ④)
- (선택과목) 성취율이 낮아도 보장지도 대상이 아니다. **출석률 미달자는 추가학습 대상**이다

미이수 처리와 학생부 기재 규칙은 `core/asa-rules.md` §8 을 따른다.
특히 **미이수 과목은 세부능력 및 특기사항을 기재하지 않는다.**

### 6단계 — 피드백

**학생용** — 성취수준별로 무엇을 알고 무엇을 할 수 있는지의 교수·학습 정보를 담는다.
학기 단위 성취수준과 부여받은 성취수준의 차이를 확인하고, 높게 평가받은 문항은 진술을 더하고 낮게 받은 문항은 감한다.

**세부능력 및 특기사항 기재 문구 틀** — 성취평가 절차의 마지막 단계(평가 결과 처리)다.
학기 단위 성취수준이 세특 기록의 준거이므로, 그 진술문에서 A~E별 서술 틀을 도출한다.

> ⚠ **개별 학생의 세특을 대신 쓰지 않는다.** 학생 실명·식별정보를 받지 않으므로 불가능하기도 하고,
> 세특은 대입 전형 자료라 교사가 관찰한 사실에 근거해 직접 써야 한다.
> 이 스킬이 만드는 것은 **수준별 서술 틀과 어휘 선택지**이며, 교사가 학생별 관찰 내용을 채워 넣는다.

틀에 담을 것
- 학기 단위 성취수준 A~E 진술문에서 뽑은 **수준별 핵심 수행**
- 관찰 가능한 외현 동사 (모호·추상적 표현, 비교육적·부정적 표현 배제)
- 평가 요소별로 "무엇을 어느 정도 했는지" 쓸 자리
- 성취수준 진술을 그대로 옮겨 붙이지 말고 **학생의 구체적 수행으로 바꿔 쓰도록** 안내

> ⚠ **미이수 처리된 과목은 과목별 세부능력 및 특기사항을 기재하지 않는다.** (`core/asa-rules.md` §8)
> 미도달 학생 명단이 나왔다면 이 점을 함께 알린다.

**교사용** — 다음 학기로 넘길 것.
- 갭 문항 수정안 · 교체할 선지
- 수업에서 보완할 오개념
- **예상 난이도 추정의 편향** — 어느 방향으로 얼마나 빗나갔는지. 이 기록을 학기마다 누적해야 추정분할점수의 정확도가 올라간다

### 7단계 — 출력

**결과 분석 보고서는 정해진 학교 양식이 대개 없다.** 이 저장소의 구성으로 만든다.
다만 학교에 양식이 있다면 그것을 우선한다 — 먼저 묻는다.

**출력 전에 `claw-hwp` 스킬 문서(`claw-hwp:hwp` 의 SKILL.md)를 먼저 읽는다.**
핸들러 목록·인자·함정·검증법이 전부 거기 있다. 소스를 뜯지 말 것. 특히 이 절들을 본다.

| 상황 | claw-hwp SKILL.md 의 해당 절 |
|---|---|
| 새 문서 생성 | "Create a new document" |
| **양식 채우기** | **"Fill in this form / 서식 / 양식 / 템플릿"** — `set_cell_text_by_label`(.hwp) · `fill_template {{토큰}}`(.hwpx) · `replace_text` 함정 |
| 기존 문서 편집 | "Edit this document" |
| 함정 모음 | "Common pitfalls" |

이 저장소에서 반드시 지킬 것만 다시 적는다.

- 키는 `operations` / `type` 이다. `ops` / `op` 로 쓰면 `ops_applied: 0` 으로 **조용히 통과**한다
- **`status: success` 만 보지 말고 `ops_applied` 를 확인한다.** 0이면 아무것도 안 들어갔다
- ops 파일을 Python 으로 쓸 때는 `write_text(..., encoding="utf-8")`. `print` 리다이렉트는 Windows 에서 cp949 로 깨진다
- 생성 후 `extract_text.js <파일> --format markdown` 으로 **역추출해 확인**한다
- 편집은 **원본 포맷을 유지**한다 (`.hwp` ↔ `.hwpx` 변환하지 않는다)

## 하지 말 것

- 학생 실명·식별정보 다루기
- 배제 없이 오개념 단정하기
- 답지반응 분포만으로 결론 내기 — 상담·후속 평가로 확인해야 한다
- 정답률이 낮은 문항을 무조건 "나쁜 문항"이라 하기 — A 수준 표적 문항은 원래 정답률이 낮다
- 표준점수를 준거참조 해석과 섞기 — 표준점수는 상대적 위치 정보다
- 결과 분석을 성적 확정 절차로 다루기 — 성적 이의신청·정정은 학업성적관리규정 소관이다
