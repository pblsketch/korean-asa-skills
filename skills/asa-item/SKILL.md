# 성취평가 문항 개발

## 이 스킬의 전제

성취평가에서 문항은 **성취수준을 판별하는 도구**다. 변별이 목적이 아니다.
따라서 "좋은 문항"의 기준이 다르다.

> 각 문항은 **어느 성취수준을 점검하는지**가 명시되어야 하고,
> 그 판단 근거는 **해당 수준 최소 능력자(MCP)의 수행 특성**이어야 한다.

**절대 건너뛰지 말 것**: 문항을 쓰기 전에 MCP 수행 특성을 먼저 진술한다.
MCP 진술이 출제 범위를 정의하므로, 이걸 건너뛰면 이후 전부가 근거를 잃는다.

### 국가 예시 평가도구를 먼저 본다 ★

조회 결과 끝에 그 성취기준의 **보급본 예시 평가도구 색인**이 붙는다.
번호·갈래(선다형/서답형/수행평가)·유형·평가 요소가 나온다.

| 상황 | 대응 |
|---|---|
| 만들려는 갈래의 예시가 **있음** | **사용자에게 먼저 알린다.** "이 성취기준에는 `〈과목명〉-2`(수행평가) 예시가 있습니다. 보급본에서 확인하시겠어요, 아니면 새로 만들까요?" 국가 개발본이 있는데 굳이 새로 만들 이유가 없을 수 있다 |
| 다른 갈래만 있음 | 그 예시의 **평가 요소를 참고**해 만든다. 평가 요소는 갈래가 달라도 유효하다 |
| **없음** | 새로 개발한다. 참고할 국가 개발본이 없다는 뜻이므로 검토를 더 꼼꼼히 한다 |

> 색인에는 **문항 본문·지문·채점기준이 없다.** 저작권상 담지 않았다(`NOTICE.md`).
> 실물이 필요하면 사용자가 보급본 원본을 열어야 한다. **본문을 지어내서 "예시 평가도구"라고 제시하지 않는다.**
>
> 색인이 아예 없으면(`subject/data/exemplars/` 미빌드) 이 절은 출력되지 않는다.
> 그때는 예시가 없다고 단정하지 말고 `python scripts/build_exemplars.py` 를 안내한다.

**학기 단위 성취수준을 반드시 함께 읽는다.** 제도 규칙상 평가도구는 성취기준 · 성취기준별 성취수준 · 영역별 성취수준 · **학기 단위 성취수준**을 모두 반영해 설계해야 한다.

```bash
ls .work/plan/          # asa-guide 가 남긴 인계 파일
```

| 상황 | 대응 |
|---|---|
| 인계 파일 있음 | `semester_levels` 를 준거로 삼고, `elements`(평가 요소)와 `min_level` 이 있으면 재도출하지 말고 그대로 쓴다 |
| 없음 | **사용자에게 학기 단위 성취수준이 있는지 묻는다.** 없다면 `asa-guide` 로 먼저 만들도록 안내하거나, 없이 진행함을 명시하고 성취기준별 성취수준만을 준거로 삼는다 |

채점기준표의 수행 수준은 **학기 단위 성취수준과 연계**되도록 구분해야 한다. 이것이 없으면 그 연계를 만들 수 없다.

### 3단계 — MCP 수행 특성 A~E 진술 ★

성취기준별 성취수준을 출발점으로, **각 수준의 최저선**에 있는 학생이 무엇을 할 수 있는지로 좁힌다.

- 성취기준별 성취수준보다 **약간 낮게** 진술되는 것이 정상이다 (평균이 아니라 하한이므로)
- 부사어 위계를 지킨다: `A 정확하게 · B 비교적 정확하게 · C 대략적으로 · D 부분적으로 · E 제한적으로`
- 인접 수준의 차이를 **한 문장으로 말할 수 있어야** 한다. 못 하면 다시 쓴다

이 진술이 각 문항의 출제 범위다.

```
A 최소 능력자의 특성  ──┐
                        ├─ 이 사이가 'B를 대표하는 문항'의 출제 범위
B 최소 능력자의 특성  ──┘
```

### 4단계 — 평가 요소 도출

성취기준을 지식·이해 / 과정·기능 / 가치·태도로 분해하고, 성취기준 해설·적용 시 고려 사항을 반영해 평가 요소를 뽑는다. 각 문항이 어느 평가 요소를 재는지 배정한다.

**가치·태도를 빠뜨리지 않는다.** 성취기준에 명시돼 있으면 반드시 평가 대상이다. 단, 관찰 가능한 수행으로 조작적 정의해야 채점할 수 있다.

### 5단계 — 유형별 문항 개발

사용자가 유형을 말하지 않았으면 묻는다. 셋 중 하나 또는 복수.

## 유형 ① 선다형 — 성취수준별 표적 5문항 세트

목표: **각 수준 MCP의 약 2/3(66%)가 정답을 맞힐** 난이도.

`subject/difficulty-levers.md` 의 레버를 **명시적으로** 적용한다. 문항마다 "어느 레버를 어느 방향으로 썼는지" 기록한다.

**E 수준의 바닥을 지킨다.** 교사들이 가장 많이 틀리는 지점이다.
E 수준 문항은 "조금 쉬운 문항"이 아니라, `difficulty-levers.md` 에 규정된 바닥까지 내려가야 한다. 그렇지 않으면 실제로는 C~D 수준이 되고 최소 성취수준 판별이 무너진다.

각 문항에 반드시 포함할 것
- 정답
- **전 선지의 해설** — 정답 근거 + 오답 4개 각각의 배제 근거
- 개발 방향: 이 문항이 무엇을 판별하는가, 인접 수준과 무엇으로 구별했는가

양식: `core/templates/item-card.md`

### 문항정보표를 함께 낸다

지필평가는 **문항정보표 작성**이 평가도구 개발 절차의 산출물이다. 교육정보시스템 입력에도 쓴다.

문항별로 담을 것 — 문항 번호 · 유형(선택형/서답형) · 내용 영역 · **성취기준** · 평가 요소 · 점검 목표 성취수준 · **예상 난이도** · 배점 · 정답

> **예상 난이도를 반드시 기록한다.** 이것이 없으면 시험 후 `asa-analyze` 가 예상–실제 갭을 볼 수 없어 결과 분석의 절반이 불가능해진다.
>
> 서답형(논술형) 채점기준표에는 **인정 범위(예시 답안·인정 답안), 풀이 과정에 따른 부분 점수, 단계별 점수**를 반드시 포함한다.

추정분할점수를 쓸 과목이면 **문항 범주화**(유형 × 난이도, 최대 6개 범주)까지 만들어 둔다. `core/cut-score.md` §3 의 4단계 입력이 된다.

양식: `core/templates/item-info-table.md`

## 유형 ② 서·논술형

목표: **목표 수준 학생이 만점 받을 확률 50%**.

- `<조건>` 이 채점기준과 **1:1 대응**해야 한다. 조건에 없는 것을 채점하거나, 조건에 있는데 채점하지 않으면 안 된다
- 조건 수와 구체성이 난이도다. A 수준은 다층 조건, E 수준은 단일 조건

- 수준별 예시 답안과 **"왜 이 수준인가"** 를 함께 쓴다

## 유형 ③ 수행평가

- **차시별 교수·학습 활동 ↔ 평가 활동을 매핑**한다. 수업에서 다루지 않은 것을 평가하면 타당도가 무너진다
- 진단·형성평가 연계와 교사·동료 피드백 지점을 명시한다
- 모둠 과제라도 개별 학생의 산출물로 평가하는 과정형 개별 평가로 설계한다

양식: `core/templates/performance-task.md` + `core/templates/rubric.md`

### 채점기준표 → 분할점수

수행 수준을 성취수준과 연계해 두면 분할점수가 자동으로 나온다.

> **각 수준 MCP가 평가 요소별로 받는 점수의 합 = 그 수준의 분할점수**

산출한 분할점수 표를 반드시 함께 낸다. **개수가 과목 유형에 따라 다르다** —
공통과목 5개(A/B, B/C, C/D, D/E, **E/미도달**), 선택과목 4개(E/미도달 없음). 절차는 `core/cut-score.md` §4.

### 6단계 — 자체 검증

내놓기 전에 전부 확인한다. 하나라도 걸리면 고쳐서 다시 검증한다.

**공통**
- [ ] 문항마다 점검할 성취수준이 명시되었는가
- [ ] MCP 수행 특성이 A~E 전부 진술되었고, 인접 수준 차이를 한 문장으로 말할 수 있는가
- [ ] 성취기준의 **교육과정 범위를 벗어난** 내용이 없는가
- [ ] 성별·지역·문화적으로 특정 학생에게 유·불리하지 않은가
- [ ] 발문이 명확한가
- [ ] 세 범주(지식·이해 / 과정·기능 / 가치·태도)가 반영되었는가

**금지 규칙** (`core/asa-rules.md` R1~R7)
- [ ] R1 (공통과목) 기본점수만으로 성취율 40%에 도달하지 않는가
- [ ] R3 측정 목적과 무관한 부차적 기능을 요구하지 않는가
- [ ] R4 수행 수준을 **과제의 복잡성이 아니라 학생의 수행**으로 기술했는가
- [ ] R5 E 수준 학생도 실제로 수행 가능한가
- [ ] R7 **수준 역전이 없는가** — 하위 수준 문항이 상위보다 어렵지 않은가

**성취평가 고유**
- [ ] 상위 수준 변별에 치우치지 않았는가 (지엽적 소재·함정 문항 금지)
- [ ] 모든 성취수준이 고르게 점검되는가
- [ ] E 수준 문항이 `difficulty-levers.md` 의 바닥까지 내려갔는가

### 7단계 — 출력

기본 산출물은 **한글 문서**다. `claw-hwp` 스킬(`claw-hwp:hwp`)의 `create.js` 로 만든다.
문항 카드 · 채점기준표 · 문항정보표를 한 문서에 담고, 모든 op 를 한 호출에 배치한다.

**페이로드 형태** — 키 이름을 틀리면 조용히 실패한다.

```json
{ "path": "문항카드.hwpx",
  "theme": "government",
  "allow_overwrite": true,
  "operations": [ {"type": "setup_document", "page_size": "a4", "margin_mm": 25}, … ] }
```

| 함정 | 대응 |
|---|---|
| 키는 `operations` / `type` 이다 | `ops` / `op` 로 쓰면 `ops_applied: 0` 으로 **조용히 통과**한다 |
| **반드시 `ops_applied` 를 확인한다** | `status: success` 라도 0이면 아무것도 안 들어간 것이다 |
| 기존 파일에 `setup_document` | `allow_overwrite: true` 없으면 거부된다 |
| ops 파일을 Python 으로 쓸 때 | `write_text(..., encoding="utf-8")` 로 직접 쓴다. `print` 리다이렉트는 Windows 에서 cp949 로 저장돼 깨진다 |

생성 후 `extract_text.js <파일> --format markdown` 으로 역추출해 내용이 실제로 들어갔는지 확인한다.

동시에 구조화 데이터를 `.work/items/<성취기준코드>.json` 에 남긴다.
`asa-analyze` 가 결과 분석 때 문항정보표로 쓴다. 최소 필드:

```json
{"code":"[성취기준 코드]","course_id":"<과목 id>","type":"selected_response",
 "mcp":{"A":"…","B":"…","C":"…","D":"…","E":"…"},
 "items":[{"no":1,"target_level":"A","element":"…","difficulty":"어려움",
           "points":4,"answer":3,"levers":{"판단 지점 수":"올림"}}]}
```

사용자가 검토용으로 먼저 보길 원하면 마크다운으로 보여 주고, 확정 후 한글로 낸다.

### `review` — 감사만 수행
이미 만들어 둔 문항·채점기준을 받아 **생성하지 않고 검증만** 한다. 교과협의회 상호 검토 대행.

6단계 체크리스트 전부 + 다음을 본다.
- 성취기준 ↔ 평가요소 ↔ 문항 ↔ 채점기준의 **추적성이 끊긴 곳**
- 수준 간 질적 구분이 불명확한 구간
- 부사어 위계 붕괴 (예: C가 D보다 약한 부사어)
- 채점 불가능한 기준 (관찰 불가능한 서술)

발견 → 근거(어느 규칙 위반인지) → 수정 제안 순으로 보고한다.

### `bootstrap` — 난이도 레버 역추출
다른 교과로 포크할 때 `subject/difficulty-levers.md` 초안을 만든다.

```
/asa-item bootstrap --standard "[코드]" --items <A~E 문항 세트>
```

같은 성취기준을 재는 A~E 문항을 받아 인접 수준 쌍마다 "무엇이 달라졌는가"를 뽑고, 반복되는 차이를 레버로 명명해(보통 4~6개) 표로 정리한다. **E 수준의 바닥이 어디인지 반드시 명시**한다.
절차 상세는 `subject/difficulty-levers.md` §5.
